Import and error model

These package names resolve to compiler standard library directories:

கொணர் "வலை"
கொணர் "பரிமாற்றம்"
கொணர் "தரவுத்தளம்"
கொணர் "கோப்பு"
கொணர் "நேரம்"

Public .uli declarations define static types, while the C emitter replaces low-level bodies with runtime intrinsics.

Network/HTTP failures return *வலை.பிழை; database failures return *தரவுத்தளம்.பிழை; file failures return *கோப்பு.பிழை. Success returns இன்மை. Always inspect the error before using associated results.

எனில் பிழை != இன்மை {
    பதிப்பி(பிழை.குறியீடு)
    பதிப்பி(பிழை.செய்தி)
    திருப்பு
}

TCP API

கேள் — listen

கேள்(முகவரி சரம்) (கேட்பி, *பிழை)

Bind and listen on ":port" or "host:port". Port 0 asks the OS for an available port.

ஏற்று — accept

ஏற்று(க கேட்பி) (இணைப்பு, *பிழை)

Block until a connection arrives. The wait parks for GC.

இணை — dial

இணை(முகவரி சரம்) (இணைப்பு, *பிழை)

Resolve and connect to an IPv4 TCP address.

படி — read

படி(இ இணைப்பு, இடம் []இருமி8) (முழுஎண், *பிழை)

Read up to நீளம்(இடம்) bytes. EOF is (0, இன்மை).

எழுது — write

எழுது(இ இணைப்பு, தரவு []இருமி8) (முழுஎண், *பிழை)

Write the complete byte slice unless an error interrupts it; count reports bytes sent.

விடு — close connection

விடு(இ இணைப்பு) *பிழை

நிறுத்து — close listener

நிறுத்து(க கேட்பி) *பிழை

முகவரி — listener address

முகவரி(க கேட்பி) (சரம், *பிழை)

Return "host:port". A wildcard 0.0.0.0 bind is exposed as 127.0.0.1 for loopback clients.

HTTP protocol behavior and limits

  • Synchronous HTTP/1.x over plain http://, IPv4 only.
  • Default port is 80; fragments are stripped; userinfo and IPv6 literals are rejected.
  • Client requests use HTTP/1.0 and Connection: close.
  • HTTP/1.1 chunked response bodies are decoded. Other transfer encodings are rejected.
  • Request/query and response header blocks are limited to 64 KiB; bodies are limited to 1 MiB decoded.
  • Query decoding maps + to space, decodes percent escapes, and keeps the last repeated key.
  • Headers are exposed with lowercase names; repeated headers are last-wins.
  • User response/request maps cannot override Host, Content-Length, Connection, Transfer-Encoding, or Content-Type.
  • Header names/values reject CR, LF, and NUL injection.
  • Redirects support absolute http:// locations for 301, 302, 303, 307, and 308. Relative redirects and HTTPS are rejected.
  • 301/302 from non-GET/HEAD and 303 convert the next request to GET; 307/308 preserve method and body.
  • Timeout currently covers socket send/receive only, not DNS resolution or TCP connection establishment.
  • No TLS, connection pooling, cookies, compression, proxy support, or streaming body API.

தரவுத்தளம் — SQL database API

The database package presents one Tamil API over an internal C function-pointer table (vtable). SQLite is the first backend; future first-party PostgreSQL/MySQL backends can implement the same operation set without changing Niraluli programs.

Database architecture and limitations

  • Runtime-loaded SQLite: generated C uses dlopen/dlsym. Building needs no sqlite3.h or -lsqlite3; the linker uses -ldl. Running needs libsqlite3.so.0 (or libsqlite3.so).
  • Opaque handles: இணைப்பு and கூற்று are typed as முழுஎண் in Niraluli but must only be used with the database package APIs.
  • Explicit lifetime: finalize every statement with கூற்றுவிடு before closing its connection with விடு. There are no database finalizers.
  • No concurrent handle sharing: do not use one connection or statement from multiple இழை in v0.62. Separate handles are allowed.
  • Transactions: issue BEGIN, COMMIT, and ROLLBACK through செயல்.
  • Not included: pooling, ORM, migrations, reflection-based scan, public third-party drivers, PostgreSQL, and MySQL.
  • Vtable scope: it is an internal backend contract, not a stable C FFI or plugin ABI.
  • SQL portability: the Niraluli API is shared, but SQL dialect and placeholder syntax may differ between future backends.
