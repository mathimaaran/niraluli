Starting concurrent work with இழை

இழை பணி(42)

இழை செயல்பாடு() {
    பதிப்பி("concurrent")
}()

இழை starts a call on a new pthread. It accepts normal calls, method calls, and immediately invoked closures. Captured closure variables follow normal by-reference closure semantics.

The generated program's main thread waits for all Niraluli-created threads before shutting down the heap and exiting.

Thread cost Niraluli currently maps each இழை to an OS thread; it does not provide Go's lightweight goroutine scheduler. Use bounded concurrency.

Channels

Types and creation

முடிவு := ஆக்கு(தடம் சரம்)       // unbuffered
வேலை := ஆக்கு(தடம் முழுஎண், 8)  // buffered

மாறி அனுப்பு தடம்<- முழுஎண் = வேலை
மாறி பெறு <-தடம் முழுஎண் = வேலை

தடம் T is bidirectional. தடம்<- T is send-only and <-தடம் T is receive-only.

Send, receive, and close

வேலை <- 10
மதிப்பு := <-வேலை
மதிப்பு, திறந்தது := <-வேலை
மூடு(வேலை)
  • Unbuffered sends rendezvous with a receiver.
  • Buffered sends block when capacity is full; receives block when empty.
  • Receive after close returns the element zero value and பொய் in comma-ok form.
  • Send on a closed channel is fatal.

Selecting communications

தடத்தேர்வு {
எனில் வேலை <- 7 {
    பதிப்பி("sent")
}
எனில் மதிப்பு, திறந்தது := <-முடிவு {
    பதிப்பி(மதிப்பு)

தடத்தேர்வு waits until a send or receive case is ready. எனில் labels communication cases; மற்றபடி is an optional non-blocking default. Closed-channel receive is ready immediately.

Ranging over channels

சுழல் மதிப்பு := ஒவ்வொரு வேலை {
    பதிப்பி(மதிப்பு)
}

Channel range receives values until the channel is closed. It accepts at most one iteration variable.

Deferred calls

செயல்பாடு கோப்பு_பயன்படுத்து() {
    வளம் := திற()
    தள்ளிவை வளம்.மூடு()

    தள்ளிவை செயல்பாடு() {
        பதிப்பி("runs first")
    }()
}

Deferred calls run in LIFO order on normal return and during panic unwind. Function arguments and receivers are evaluated when the defer statement executes, not later.

  • A deferred value-receiver method captures a receiver copy.
  • A deferred pointer-receiver method on an addressable value captures its address.
  • தள்ளிவை done is zero-argument sugar for தள்ளிவை done().

Panic and recover

செயல்பாடு பாதுகாப்பாக() {
    தள்ளிவை செயல்பாடு() {
        செய்தி := மீள்()
        எனில் செய்தி != "" {
            பதிப்பி("recovered: " + செய்தி)
        }
    }()

    அலறு("something failed")
}

அலறு accepts சரம், முழுஎண், மிதவைஎண், நிலை, இருமி8, or இருமி32; primitive values are stringified. The panic state is per thread.

மீள்() only stops an active panic when called from deferred execution. It returns the panic string. Otherwise it returns "". An uncaught panic prints Niraluli function frames and aborts the process.

There is no interface/any panic payload in v0.77.

Managed heap and garbage collection

The C backend uses a malloc-backed stop-the-world conservative mark/sweep collector. Allocation is implicit for strings, slice/map growth, closures, channels, defer thunks, networking buffers, and runtime objects.

Collection model

  1. Allocation checks the current heap trigger.
  2. A collector requests all registered Niraluli threads to stop or park.
  3. Thread stacks and captured register sets are scanned conservatively.
  4. Interior-looking pointers are resolved through a sorted object index.
  5. Reachable heap objects are recursively marked; unmarked objects are freed.
  6. The next trigger is based on live heap size, with safe growth for large single allocations.

Safe points and blocking

  • Generated functions and loop back-edges poll for collection.
  • Channel waits park through a GC-aware condition wait.
  • TCP, UDP, and HTTP blocking I/O parks the current thread.
  • SQL calls through தரவுத்தளம் also block the calling thread while waiting on the native backend.
  • File I/O through கோப்பு parks the calling thread during blocking reads/writes.
  • Sleep through நேரம்.உறங்கு parks the calling thread during nanosleep.
  • Register roots are captured with setjmp, required for optimized -O2 builds.
Conservative semantics The collector may retain unreachable objects when ordinary integer/byte data resembles a heap address. This affects reclamation precision, not program correctness.
