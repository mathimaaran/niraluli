go run ./cmd/uli

Compilation pipeline

  1. Expansion: input files/directories are expanded; imported directories are recursively loaded.
  2. Lexing: UTF-8 source becomes tokens; Go-like semicolon insertion runs here.
  3. Parsing: recursive-descent parser produces the Niraluli AST.
  4. Package merge: same-package files are merged in dependency order.
  5. Checking: names, visibility, types, method sets, generic instantiations, closure captures, and entry rules are validated.
  6. C emission: typed program metadata drives generated C types, runtime inclusion, monomorphization, and function bodies.
  7. C compilation: GCC is preferred, then cc; generated C11 links pthread.
  8. Execution: run launches the absolute binary path and forwards stdout/stderr.

Output files and build flags

Default output base comes from the input filename or directory:

go run ./cmd/uli build corpus/tamil/வணக்கம்.uli
# build/வணக்கம்.c
# build/வணக்கம்

Override the binary output:

go run ./cmd/uli build -o dist/hello hello.uli
# dist/hello.c
# dist/hello

emit -o generated/program adds the .c extension when missing.

Optimization

  • Default: -O2.
  • Debug/unoptimized: --debug or -O0.
  • Explicit: -O1, -O2, -O3, or -Os.

The effective C invocation is equivalent to:

gcc -std=c11 -O2 -pthread generated.c -o program -ldl

-ldl is required so the SQL runtime can dlopen SQLite. Programs that never import தரவுத்தளம் still link it today; the driver always passes -ldl.

Package loading

  • A directory input loads its .uli package files.
  • Relative import paths resolve from the importing package directory.
  • "வலை", "பரிமாற்றம்", "தரவுத்தளம்", "கோப்பு", and "நேரம்" resolve from stdlib/.
  • Dependency packages are checked/emitted before dependents.
  • Cycles and unresolved package names are hard errors.
  • The entry package defaults to தொடக்கம்.

Testing

go test ./...

The suite includes:

  • Lexer/parser/checker unit and corpus tests.
  • C emitter structural and compile/run tests.
  • Runtime tests for strings, slices, maps, defer, panic, concurrency, and GC.
  • Package-loader integration tests for TCP, UDP, HTTP loopback behavior, and SQL (TestDatabaseProgram).

Network integration tests bind loopback/ephemeral ports. Database tests require a runtime SQLite shared library. Run them in an environment that allows local sockets and can resolve libsqlite3.so.0.

go test ./internal/load -run TestDatabaseProgram -count=1
go test ./internal/load -run TestUDPProgram -count=3
go test ./internal/load -run TestHTTPRedirectOptions -count=1

Adding a language feature

The project uses closed Tamil-0.x slices. A typical feature should update all affected layers:

  1. Add a dated decision to notes/design-decisions.md.
  2. Lock spelling/syntax in grammar/tamil/keywords.yaml and grammar/tamil/ebnf.md.
  3. Add or update a construct card under grammar/tamil/constructs/.
  4. Add a focused corpus example, and an invalid example when diagnostics matter.
  5. Implement lexer/parser/AST changes when new syntax is required.
  6. Implement checker types and semantic validation.
  7. Implement C emission/runtime support.
  8. Add unit and compile/run integration tests.
  9. Update roadmap, deferred inventory, README, and these HTML docs.
No syntax change? Standard library/runtime additions often need only public stdlib/*.uli declarations, checker-compatible signatures, emitter intrinsics, C runtime code, corpus, tests, and documentation.

Debugging generated C

  1. Use check first to isolate frontend errors.
  2. Use emit to inspect C without invoking the compiler.
  3. Build with --debug to disable optimization.
  4. Compile the emitted file manually with extra warning/sanitizer flags when appropriate.
go run ./cmd/uli emit -o build/debug program.uli
gcc -std=c11 -O0 -g -pthread \
  -fsanitize=address,undefined \
  build/debug.c -o build/debug
./build/debug

Generated identifiers are UTF-8-safe C-mangled names. Runtime helpers retain readable uli_* names such as uli_alloc, uli_http_do_opts, uli_net_udp_recv, and database helpers under uli_db_*.
