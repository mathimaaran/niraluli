Lexer, parser, and AST

  • The lexer handles Unicode identifiers, Tamil decimal digits, strings/comments, and Go-like semicolon insertion.
  • The parser is hand-written recursive descent with explicit precedence levels for expressions.
  • The AST preserves source positions for diagnostics and has nodes for declarations, statements, type expressions, and value expressions.
  • Language syntax is specified in grammar/tamil/ebnf.md; construct cards contain semantics and examples.

Checker and typed program model

The checker runs package-by-package after all package names/imports are registered. Its shared ProgramInfo records:

  • Expression types and named/underlying type relationships.
  • Struct fields, pointer elements, slices, arrays, maps, channels, tuples, and function signatures.
  • Imported package/local qualifier mappings and export visibility.
  • Generic call instantiations for monomorphization.
  • Method values/expressions and package function values.
  • Closure capture sets and locals promoted to heap storage.

Types use compact internal IDs with ranges for named, defined, pointer, slice, tuple, array, map, channel, function, and type-parameter classes.

The checker rejects unsupported contexts early: invalid aggregate members, non-comparable equality, bad method sets, unused imports, import cycles, assignment arity mismatches, and malformed entry packages.

Names and declarations

Tamil/package identifiers are encoded into legal collision-resistant C identifiers. The emitter writes forwards before dependent aggregate bodies, orders nested structs topologically, and creates helper functions for equality, printing, slice operations, maps, calls, and closure trampolines.

Generics

Generic functions are monomorphized from checker-recorded instantiations. Each concrete type argument combination receives a generated C function. There is no dynamic generic dispatch.

Closures and methods

Function values pair a trampoline pointer with an environment pointer. Captured locals are promoted when needed, and closures store references in managed heap environments. Bound methods save their receiver; method expressions use an unbound receiver-first function shape.

Intrinsic packages

Public Niraluli signatures in stdlib/ are normal declarations for loading/checking. During emission, known package functions are replaced with calls into embedded C runtime helpers. Higher-level exact-path mux logic remains implemented in Niraluli. The database package embeds db_runtime.inc: an internal uli_db_vtable of operation pointers, with SQLite filled in through dlopen/dlsym so future first-party engines can share one Tamil API.

Known limitations

Language surface

  • No interfaces, interface values, constraints, generic types, or generic methods.
  • No top-level variables.
  • No bitwise operator family, richer integer widths, or complex numbers; constants lack iota and parenthesized groups.
  • No directory/seek/chmod filesystem APIs beyond basic கோப்பு open/read/write; no timers/tickers/parse beyond basic நேரம்; formatting is %s-over-strings only (no typed %d); no slice... expand; no JSON, crypto, or TLS packages.
  • Panic/recover payload is string-oriented, not arbitrary values.

Runtime and platform

  • Linux/POSIX only; IPv4 only.
  • Each இழை is a pthread, not a lightweight user-space task.
  • Conservative GC may retain false-positive objects and is stop-the-world.
  • No race detector, sanitizer integration in the driver, finalizers, or deterministic memory release.
  • Several programmer faults abort instead of producing recoverable typed errors.

HTTP/network backlog

  • Dial and DNS timeouts.
  • Relative redirects.
  • HTTPS/TLS, IPv6, proxies, pooling, streaming, compression, cookies.

Database backlog

  • PostgreSQL and MySQL implementations of the internal backend vtable.
  • Connection pooling and safe concurrent sharing of one database handle.
  • A stable public driver/plugin ABI, ORM, migrations, and reflection-like row mapping.

Roadmap

  1. NASM x86-64: introduce a small target-neutral IR and emit Linux ELF through NASM.
  2. i386 Linux: add a second native architecture after x86-64 stabilizes.
  3. SQL backends: first-party PostgreSQL/MySQL implementations of the internal vtable when needed; pooling and concurrent handle policy later.
  4. Optional backlog: networking leftovers and interfaces only when concrete use cases justify them.
  5. Larger Go-inspired features: richer generics/constraints only if they earn their complexity.

The current C backend remains the semantic reference while the native backend begins.

Public project status

Niraluli v0.67 is suitable for public release as an experimental research compiler. It should not be described as production-ready.
